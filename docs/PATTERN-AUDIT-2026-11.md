# Tundra patterns for a filesystem-native runtime

This is a source audit for [issue #100](https://github.com/ryanmaclean/tundra/issues/100), based on Tundra main commit `41b939d1928558bd6a2c865ee9050b36f5d0c616`. The classifications are recommendations for Moth-BOP and smolFire, not claims that their current implementations provide the described guarantees. No code was copied and no runtime or test was executed for this audit. A port must separately establish dependency licensing, security and behavior.

| Area | Classification | Candidate and boundary |
| --- | --- | --- |
| Provider failover and routing | Adapt into Moth-BOP | Take the explicit retry/give-up distinction, priority ordering, bounded circuit-breaker and rate-limit ideas. Do not copy the profile management API or assume that selecting a model actually retries a different provider. |
| Token and context budgets | Adapt into Moth-BOP | Keep per-task accounting and select only the context needed for a task. A filesystem supplies durable source material; it does not provide a model token budget, concurrency-safe reservations or an accurate tokenizer. |
| Datadog telemetry | Adapt into Moth-BOP | Reuse the concepts of bounded-cardinality counters, timings and request correlation. Add and verify an actual Agent/OpenMetrics or OTLP integration before claiming Datadog delivery; the inspected tracing helper alone generates IDs and spans. |
| Approval and security gates | Adapt into Moth-BOP | Preserve explicit allow, require-approval and deny decisions and deny-by-default handling for unknown operations. Bind approvals to the exact action and durable state before use; do not assume the in-memory approval vector is itself an audit chain. |
| Event bus | Unnecessary for durable state/history if a filesystem-native journal and replay cursor already provide the required ordering and recovery | An optional in-process bus can accelerate transient notifications. Consumers must detect loss and reconcile from the durable journal; filesystem storage by itself does not implement fan-out, cursor semantics or wakeups. |
| PTY and session lifecycle | Adapt into Moth-BOP | Preserve the capacity limit and bounded I/O channels, but implement and test ownership, cancellation, child reaping and slot release as one lifecycle. Do not copy the existing pool as a proven leak-free supervisor. |

## Evidence and constraints

- **Routing.** [`ProfileRegistry` and `ResilientRegistry`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-intelligence/src/api_profiles.rs#L206) provide ordered profiles, circuit-breaker/rate-limit state and an explicit retry verdict. [`ModelRouter::execute`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-intelligence/src/model_router.rs#L154) accepts a single provider and propagates its error; its model-selection fallback is not by itself evidence of cross-provider retry. Before porting, specify idempotency, total deadlines, credential isolation, retry classification and exhausted-provider behavior.
- **Budgeting.** [`ContextNode::estimated_tokens`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-core/src/context_engine.rs#L59) estimates tokens from byte length divided by four. [`collect_context`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-core/src/context_engine.rs#L179) sorts by relevance and stops at the first over-budget candidate; it does not use its task ID. [`ModelRouter::execute`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-intelligence/src/model_router.rs#L154) checks budget before the request and consumes actual usage afterwards. That source ordering alone does not prove atomic reservations under concurrent calls.
- **Telemetry.** [`MetricsCollector`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-telemetry/src/metrics.rs#L119) records counters, gauges and histograms and exposes Prometheus/JSON representations. [`request_id_middleware`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-telemetry/src/tracing_setup.rs#L26) creates correlation fields. Those source facts do not establish an exporter, trace-parent propagation, delivery to Datadog or safe label cardinality in a deployment.
- **Approvals.** [`ToolApprovalSystem`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-agents/src/approval.rs#L105) stores policy and pending/resolved approvals in memory; unknown tools require approval. The inspected file does not record requests in an `AuditChain`. Persistence, one-time consumption, actor/action binding and crash recovery require separate design and tests.
- **Events.** [`EventBus`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-bridge/src/event_bus.rs#L25) uses bounded 1,024-item channels and removes disconnected or full subscribers rather than blocking the publisher. It is a useful loss-policy example, not a durable queue or replay log. Require a sequence/cursor and explicit gap recovery if it fronts a filesystem journal.
- **PTYs.** [`PtyHandle::kill`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-session/src/pty_pool.rs#L311) asks the child to terminate. [`PtyPool::kill`](https://github.com/ryanmaclean/tundra/blob/41b939d1928558bd6a2c865ee9050b36f5d0c616/crates/at-session/src/pty_pool.rs#L800) only removes the tracking entry; its own documentation requires the caller to kill the handle separately. No `Drop` implementation in this file proves automatic child termination and slot release. Test actual child/descendant exit, full queues, partial spawn failure, cancellation and interrupted cleanup before adopting the pattern.

The earlier draft [PR #102](https://github.com/ryanmaclean/tundra/pull/102) contains useful context, but its direct-reuse and automatic-cleanup assertions should not be treated as current acceptance evidence. This audit does not establish that any recommendation has been implemented in another project.
